# Roadmap

## Цели

- Kill switch для VPN-клиентов, в которых его нет или он сложно настраивается.
- Проект для личного использования; заодно практика работы с AI-инструментами.
- Разрабатывался и тестировался только с Happ; технически возможна поддержка других клиентов.

### Этапы

1. Выбор технологии для интерфейса (exe, собранный через PS2EXE, выдаёт ошибку после выхода компьютера из сна).
2. Git и аудит текущего кода.
3. Рефакторинг или переписывание на выбранной технологии.
4. Расширение функциональности (например, поддержка интерфейсов других VPN-клиентов).

## Решения

- **2026-11-07** — Работа строится по схеме «сначала обсуждение плана и уточняющие вопросы, затем изменения». Чтение и анализ выполняются без обсуждения.
- **2026-11-07** — Правила разделены на общие (`~/.claude/CLAUDE.md`, действуют во всех проектах) и проектные (`./CLAUDE.md`). Цель: переиспользовать общие правила в других проектах.
- **2026-11-07** — Документация проекта хранится в `docs/`, roadmap лежит в `docs/ROADMAP.md`. Решения пока фиксируются в этом разделе; если их станет много, перейдём на ADR (`docs/decisions/`).
- **2026-11-07** — Комментарии в коде пишутся на английском, общение и документация ведутся на русском (общее правило).
- **2026-11-07** — Технология выбирается до рефакторинга, чтобы не рефакторить код, который потом будет переписан. Git и аудит тоже отложены до выбора технологии.
- **2026-11-07** — Новая технология: C# на .NET Framework 4.8 (WinForms). Причины: встроен в Windows 10/11, ничего не нужно ставить; маленький exe; логика переносится почти напрямую; масштабирование решается манифестом PerMonitorV2 и нативным `ContextMenu`. Rust отклонён: изучение языка не цель, кода больше.
- **2026-11-07** — Блокировка остаётся включённой после выхода из программы или её падения: это и есть смысл kill switch. Менять не нужно.
- **2026-11-07** — План перехода: установить .NET SDK 8 через winget → git → краткий аудит (`docs/AUDIT.md`) → переписывание в `src/Sveto4/`, старые файлы в `legacy/` → сборка; запускает и проверяет пользователь. Коммит после каждого завершённого этапа.
- **2026-11-07** — Версия 2 переносит поведение старой без изменения функциональности. Отличия: оранжевое состояние «частично включено» с пунктами Turn ON/OFF для всех профилей; правила получают группу `Sveto4`; одновременно запускается только одна копия; ключ `--auto-enable` (принимается и старый `-AutoEnable`).
- **2026-11-07** — Именование не меняем: код и структура (`src/Sveto4/`, `Sveto4`) по соглашениям C#.
- **2026-11-07** — Юнит-тесты проверяют только логику, реальный файрвол не затрагивают. Проверку работы с файрволом выполняет пользователь вручную; позже можно обсудить автотесты в Windows Sandbox.
- **2026-11-07** — Утечки через системные правила (AUDIT п. 1): системные правила не трогаем, программа только предупреждает о них. Варианты «отключать правила», «запрещающие правила KS-Block» и WFP отложены.
- **2026-11-07** — Пересмотр решения об утечках: вариант А. На время блокировки программа отключает системные правила DNS, IPv6, Teredo, IP-HTTPS, запоминает их и включает обратно при выключении. Есть переключатель «Block system leaks» (по умолчанию включён); если он выключен, работает только предупреждение. Причина переключателя: если Happ ищет сервер через DNS Windows, при упавшем VPN он не переподключится. Как Happ находит сервер, выяснить не удалось: в DNS-кэше Windows адреса сервера нет, xray соединяется сам.
- **2026-11-07** — Меню: блок «Block system leaks» и «System leaks blocked / Possible leaks» стоит над Reset ALL. Значок ⚠ только в конце строки (выравнивание табуляцией): у «Possible leaks», «Partially on» и у пропавшего интерфейса.
- **2026-11-07** — Выбранный, но пропавший или отключённый интерфейс остаётся активным и отмеченным, справа пометка `⚠ Not found` или `⚠ Disconnected`; щелчок снимает выбор.
- **2026-11-07** — Меню следует теме Windows (светлая/тёмная) через недокументированные функции uxtheme; при недоступности остаётся светлым.
- **2026-11-07** — Ускорение: при чтении правил и при отключении/восстановлении системных правил — один проход по правилам файрвола вместо нескольких; длительность операций пишется в журнал.
- **2026-11-07** — Запаздывание галочки решено прогнозом: после щелчка меню сразу показывает ожидаемое состояние, затем перечитывает его из файрвола. Вариант «показывать идущую операцию» отклонён.
- **2026-11-07** — Подсказка трея до 127 символов (предел Windows) через запись внутреннего поля NotifyIcon; если приём не сработает, обрезается до 63.
- **2026-11-07** — Профили VPN-клиентов вместо поиска по подстроке «happ/hiddify». Профиль описывает клиента данными (описание и префикс имени адаптера, процессы для поиска папки, папка по умолчанию, исключаемые exe), чтобы позже добавить импорт профилей. Встроен профиль Happ; Hiddify убран (не используется).
- **2026-11-07** — Профиль разрешает все exe из папки клиента, а не только запущенные: ядро, запущенное позже (sing-box, tun2proxy), сразу может подключиться к серверу.
- **2026-11-07** — Адаптеры клиента синхронизируются автоматически: новые разрешаются, пропавшие удаляются (удаление разрешающего правила только сужает доступ). Реакция по событию `NetworkAddressChanged` (~0,5–1 с), опрос раз в 3 с остаётся запасным.
- **2026-11-07** — Профили в отдельном подменю «VPN clients» над Interfaces; там же позже появится импорт. «None» выключает и профили.
- **2026-11-07** — Автозапуск: задача Планировщика `Sveto4` (при входе текущего пользователя, наивысшие права, без UAC), запускается без `--auto-enable`, потому что блокировка и так переживает перезагрузку, а осознанный OFF не должен отменяться. Пункт «Start with Windows» стоит отдельным блоком над Exit. Reset ALL автозапуск не трогает. Задача переключается на новый путь сама, только если файл из неё пропал. Если она запускает другую существующую копию, сама не перехватывается, чтобы тестовая сборка не подменяла автозапуск.
- **2026-11-07** — «Allow NAT (WSL)» заменён на «Allow WSL»: правило файрвола Hyper-V `KS-WSL-Allow` для WSL вместо правила «весь трафик процесса System». Причина: правило для System пропускало трафик мимо VPN. Эксперимент показал, что правила Hyper-V достаточно, а при упавшем VPN WSL блокируется. Отдельный пункт «Allow system traffic» не добавляется: для kill switch это опасная галочка, а польза не подтверждена. Старое правило удаляется при запуске, включённое превращается в «Allow WSL». Запись идёт через WMI (`root\StandardCimv2`).
- **2026-11-07** — Адаптеры с «иероглифами» не скрываются по символам имени: у пользователей с китайской Windows такие имена законны. Сначала собираем диагностику (имя, коды символов, описание) и скрываем по описанию.
- **2026-11-08** — Импорт профилей: формат JSON (встроенный в .NET 4.8 сериализатор), хранение в `%ProgramData%\Sveto4\profiles\`, права на `%ProgramData%\Sveto4` только у администраторов (профиль открывает сеть программам). `id` без `-`, чтобы префиксы правил разных профилей не пересекались. Ошибка импорта показывается окном: это действие пользователя, и без окна он не узнает причину. Профиль NekoBox не встраивается, а лежит образцом.
- **2026-11-08** — Portable-режим вынесен отдельным шагом.
- **2026-11-08** — Публикация в open source: репозиторий `Sveto4` на GitHub; адрес автора в истории заменён на `…@users.noreply.github.com` (история переписана до публикации); лицензия MIT; `README.md` на английском, `README.ru.md` на русском, внутренние документы на русском; `CLAUDE.md` остаётся в репозитории; CI на GitHub Actions (тесты, релиз по тегу `v*` с SHA-256). exe не подписывается.
- **2026-11-07** — В правила проекта добавлен запрет запускать скрипт и менять файрвол без явного разрешения, а также напоминание пересобирать exe после правок.

## Идеи (не утверждены)

- В меню периодически появляется адаптер с «иероглифами» (например, `长诲阐`). Вероятно, это временный TUN-адаптер в момент создания, пока у него ещё нет нормального имени (не проверено). Теперь такие адаптеры записываются в журнал строкой `New adapter: …`.

- WFP (Windows Filtering Platform) вместо правил файрвола: собственные фильтры, которые срабатывают поверх любых системных разрешений. Надёжнее, но кода в 3–4 раза больше; нужна проверка в Windows Sandbox. Отложено.

## Требования к новой версии

- Проверять все три профиля файрвола (Domain, Private, Public). Если они расходятся, показывать состояние «частично включено» с пояснением, что произошло, и действием «Выровнять» (применить текущий режим ко всем профилям).
- Обрабатывать ошибки и выход компьютера из сна без всплывающих окон.
- Корректно масштабироваться (PerMonitorV2, нативное меню, размер иконки по системе).
