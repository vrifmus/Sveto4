# Аудит PowerShell-версии (2026-11-07)

Разбор `legacy/sveto4.ps1` перед переписыванием на C#. Важность: 🔴 высокая, 🟡 средняя, ⚪ низкая.

## Защита (утечки трафика)

### 🔴 1. Существующие разрешающие правила Windows обходят блокировку
Kill switch переключает `DefaultOutboundAction` на `Block`. Это блокирует только трафик, для которого **нет** разрешающего правила. На этой машине включено **197** исходящих Allow-правил, не созданных программой. Среди них:
- `Core Networking - DNS (UDP-Out)`: DNS-запросы системы могут уходить через Wi-Fi мимо VPN (**утечка DNS**);
- `Core Networking - IPv6 (IPv6-Out)`, `Teredo (UDP-Out)`, `IPHTTPS (TCP-Out)`: системные туннели IPv6;
- правила приложений Store, удалённого помощника, Cast to Device и др.

**Решение (2026-11-07, пересмотрено):** вариант (а) с переключателем «Block system leaks». При выключенном переключателе работает только предупреждение («Possible leaks»). Свойства правил проверены: DNS-правило разрешает службе `dnscache` UDP 53 на любой адрес через любой адаптер.

Насколько реальна каждая утечка, нужно проверить отдельно: многие правила ограничены конкретной службой или портом. Варианты решения обсудим отдельно:
- (а) на время работы kill switch отключать «опасные» системные правила и включать их обратно при выключении;
- (б) показывать предупреждение со списком правил;
- (в) фильтровать через WFP (Windows Filtering Platform) напрямую, как это делают VPN-клиенты. Это надёжнее, но значительно сложнее.

### 🟡 2. Совпадение имени процесса по подстроке — решено 2026-11-07 (профиль клиента: exe из папки клиента)
Правила `KS-App-*` выдаются любому процессу, в имени которого есть `happ` или `hiddify`, и всем его дочерним процессам. Посторонняя программа с похожим именем получит доступ в сеть. Нужно сопоставлять точнее: по пути установки клиента или по списку известных exe.

### ⚪ 3. «Allow NAT (WSL)» разрешает весь трафик процесса `System` — решено 2026-11-07 (правило Hyper-V `KS-WSL-Allow`)
Это ядро Windows: через него идут SMB, часть сетевых служб и т.д., на любом интерфейсе. Для WSL это может быть шире, чем нужно. Стоит проверить, хватит ли разрешения только для подсети WSL.

**Проверка (WSL 2, режим NAT, подсеть `172.20.144.0/20`):** трафик WSL сначала проходит файрвол Hyper-V. В него подмешиваются блокировка и правила основной системы, но правила по интерфейсу там не действуют. Без разрешающего правила WSL остаётся без сети. С правилом Hyper-V только для WSL (без правила для System) WSL выходит через VPN, а при отключённом VPN блокируются и WSL, и Windows. Правило для System выпускало и WSL, и системный трафик через Wi-Fi мимо VPN. Оно удалено, отдельного пункта для него нет.

### ⚪ 4. Allow LAN не включает link-local IPv6 (`fe80::/10`) — решено 2026-11-07 (подсеть добавлена)
Некоторым устройствам в локальной сети это может помешать. Нужно решить, добавлять ли.

## Надёжность

### 🔴 5. Необработанные ошибки (причина окон после сна)
`Get-NetAdapter` и командлеты файрвола вызываются без обработки «нефатальных» ошибок. После выхода из сна адаптеры переподключаются, вызовы на короткое время падают. В exe, собранном PS2EXE с `-noConsole`, любая такая ошибка показывается окном. При прямом запуске скрипта она уходит в скрытую консоль.

### 🟡 6. Состояние определяется только по профилю Public
См. ROADMAP, «Требования к новой версии».

### 🟡 7. Повторный вход во время операции
Анимация иконки вызывает `DoEvents()`. В этот момент может сработать таймер или повторный клик по меню, и тогда операции наложатся. Флаг `IsAnimating` сбрасывается внутри анимации ещё до окончания самой операции. Если операция бросит исключение, состояние не восстанавливается: нет `try/finally`.

### 🟡 8. Флаги меняются до того, как действие выполнено
`Toggle-AllowLAN` и `Toggle-AllowNAT` сначала переключают флаг, потом создают правило. Если создание не удалось, меню покажет неверное состояние. Флаг нужно определять по факту, перечитывая правила.

### ⚪ 9. Работа с файрволом в потоке интерфейса
Пока выполняются командлеты (до нескольких секунд), меню и иконка не отвечают.

## Интерфейс

### 🟡 10. Плохое масштабирование
Процесс не объявляет поддержку DPI, `ContextMenuStrip` рисуется растянутым, иконка всегда 24×24. Решение: манифест PerMonitorV2, нативный `ContextMenu`, размер иконки из `SystemInformation.SmallIconSize`.

### ⚪ 11. Адаптеры с «мусорными» именами
В списке интерфейсов показываются все адаптеры, кроме отключённых, в том числе временные (см. ROADMAP). Предлагается показывать рядом описание адаптера.

## Что переносим без изменений

- Логику режимов: блокировка через `DefaultOutboundAction`, разрешение по интерфейсу, LAN, NAT, Reset ALL.
- Префикс `KS-` и формат имён правил, чтобы новая версия подхватывала правила старой.
- Восстановление состояния из файрвола при запуске.
- Блокировка остаётся после выхода или падения программы.
- Цвета иконки и их смысл, опрос раз в 3 секунды.
- Параметр `-AutoEnable` (в C# он станет `--auto-enable`).
